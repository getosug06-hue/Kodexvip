# Раздел «Ивенты»: подключение

## Что добавлено

В `index.html` добавлен раздел «Ивенты» для студенческого кабинета и полная панель управления для администратора. Поддерживаются типы «Сессии», «Учебная практика» и «Производственная практика», даты начала и окончания, лимит мест, индикатор свободных мест с зелёным открытым или красным закрытым замком, отдельные формы записи, изменение данных записи, статусы «Не оплачен», «В процессе...» и «Готов», комментарий администратора и файлы результатов.

В шапке студента теперь два независимых счётчика: красный для новых материалов и жёлтый для новых событий, свободных мест и готовых результатов. Уведомление об ивенте открывает конкретное событие. Результат любого ивента загружается только как PDF, открывается прямо на сайте или в отдельной вкладке и доступен для скачивания.

## Подключение базы

Откройте **Supabase → SQL Editor**, вставьте содержимое файла `events_schema.sql` и выполните его целиком. Скрипт создаёт таблицы `events` и `event_registrations`, индексы, триггеры обновления времени, функцию атоматической записи с защитой от переполнения лимита и публичный Storage bucket `event-results`.

После выполнения обновите страницу сайта. Если в браузере осталась старая версия, очистите кеш или выполните принудительное обновление страницы.

## Как работать администратору

В админке заполните название, тип, даты, количество мест и, при необходимости, описание. После создания событие сразу появляется у студентов. В карточке события можно изменить даты и увеличить или уменьшить лимит, удалить событие, увидеть список записавшихся и их заполненные формы.

Для каждой записи выберите статус. При статусе «Готов» добавьте комментарий и файл: для любого типа ивента — PDF. Нажмите «Сохранить запись». Студент увидит зелёный статус, комментарий, кнопку просмотра и кнопку скачивания.

## Важное ограничение текущей архитектуры

Существующий портал использует ключ доступа и клиентский Supabase без серверной авторизации. Поэтому SQL-скрипт сохранён в совместимом с текущим проектом варианте, а проверка владельца записи выполняется на клиенте через идентификатор профиля. Для публичного коммерческого запуска рекомендуется перенести админские операции и загрузку файлов на серверные Edge Functions и включить строгие RLS-политики. Пароль для сессии сейчас сохраняется в `form_data` в соответствии с исходным требованием; если внешняя площадка поддерживает одноразовые токены, безопаснее использовать их вместо постоянного пароля.

## Обновление от сентября 2026

Перед публикацией новой версии сайта откройте **Supabase → SQL Editor**, вставьте содержимое файла `supabase_migration_2026_09_event_fixes.sql` и выполните его один раз. Миграция добавляет статус «Не оплачен» по умолчанию и политики для загрузки, просмотра, замены и удаления PDF в bucket `event-results`. Без неё Supabase будет отклонять загрузку с ошибкой Row Level Security.

После миграции при новой записи студент автоматически получает статус **«Не оплачен»**. В админке его можно изменить на «В процессе...» или «Готов». Кнопка «Удалить студента» удаляет только запись на ивент и сразу освобождает место.
